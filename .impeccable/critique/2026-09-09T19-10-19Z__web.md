## Design Specificity Verdict

Strongly authored for this product — not category-interchangeable. The decisive evidence is the Format Morph: the source-to-target chip pair joined by an animated gradient stream, reused as the atomic brand unit in the logo, Landing hero, Convert hero, every Queue/History row, empty states, and even the PageLoader (a live PDF->DOC morph as the spinner). Only a conversion tool would use it. The format-color system is applied only to chips/morph streams — disciplined. The "precision graphite" palette deliberately avoids the stock black-and-lime SaaS default.

Detector confirms a clean base: 0 findings across 44 markup files (engine impeccable-engine 0.1.5, exit 0, no config suppression). Where it drifts generic: the Footer Product/Company/Legal trio, the Billing transactions table, the Settings profile form, and the four-stat Dashboard are off-the-shelf SaaS patterns — a thin generic crust on the supporting/admin screens.

## What's Working

1. The Format Morph as a real brand system — not a logo but an interaction. Threading a live PDF->DOC morph through the logo, hero, every queue/history row, empty states, and the loading spinner creates a signature no rival has, and directly dramatizes the product's one job. The single most valuable design decision in the codebase.
2. "Watch it happen" is implemented, not copy. StatusBadge pulses by state; ProgressBar draws a source-color -> target-color gradient (not a generic accent); SSE live updates make the promise felt. Emerald=done, rose=failed, pulse=in-flight are legible at a glance.
3. Rarely-seen error prevention + recovery care. Validation before upload, folder duplicate prevention, self/descendant move guards, friendlyErrorMessage mapping, and a retry path that falls back cached file -> re-upload -> navigate pre-filled when the source object is gone.

## Priority Issues

### [P0] Settings "Delete account" is a broken, high-stakes dead-end
- What: SettingsPage.deleteAccount() runs window.confirm(...) then shows error("Account deletion is not available yet."). It never deletes.
- Why it matters: The single most consequential, high-trust moment on a security-focused product. Confirming and getting "not available yet" is a betrayal that erodes the exact trust the Security page builds.
- Fix: Replace with the styled destructive Modal (as History/Files already do). Either implement deletion, or present it truthfully — "Account deletion is temporarily unavailable. Contact support." with a real link. Never confirm then error.
- Suggested command: harden

### [P1] window.confirm breaks the design language in Settings + Billing
- What: Settings deletion and Billing cancellation use native window.confirm, while History and Files use the accessible, themed Modal.
- Why it matters: The jarring OS dialog is visibly off-theme and inconsistent with the app's own (better) confirmation pattern — so the highest-stakes actions are the ugliest.
- Fix: Route all destructive confirmations through the existing Modal-based DeleteConfirmModal. Net-new: cancellation confirmation in Billing.
- Suggested command: polish

### [P1] History filter bar exceeds 4 visible options at a decision point
- What: The History toolbar shows 6 format chips + a 4-option time-range dropdown + a 5-option status dropdown simultaneously. Queue sort = 5 options; History status = 5 options.
- Why it matters: Violates minimal-choices and chunking (2 hard cognitive-load failures). Users can't hold 6 formats x 4 ranges x 5 statuses in working memory at once.
- Fix: Make format chips a primary-4 row with a "More" disclosure, or fold all three filters into a single "Filter" control with active-filter badges. Keep <=4 visible at rest.
- Suggested command: distill

### [P1] Dead placeholder links undermine trust on a security product
- What: Footer Privacy / Terms / GDPR / About / Blog / Careers are all href="#"; Support "Documentation" -> /docs and "Status page" -> /health (no such routes).
- Why it matters: On a product whose entire Persuade strategy is "we take your files seriously", non-functional legal + docs links read as unfinished and contradict the ISO/27001 story.
- Fix: Wire real routes/pages or demote the links to inert text until they exist. Never ship href="#" on a compliance page.
- Suggested command: harden

### [P2] Each Files card carries a 6-item menu + a star + drag affordances
- What: Every FileCard shows thumbnail, name, star toggle, and a CardMenu with Move/Download/Convert/Favorite/Rename/Delete (6 items). "Favorite" appears twice (star + menu).
- Why it matters: High per-card cognitive load and tiny hit targets; noisy on a full library.
- Fix: Split into primary actions on the card (Download, Convert) and a leaner overflow for secondary. Fold "Favorite" into the star only.
- Suggested command: distill

### [P2] Queue sorts "By filename" where the spec (and users) expect "By size"
- What: QueuePage replaces the spec's "By size" with "By filename" because the backend doesn't return size.
- Why it matters: A defensible code choice but a UX surprise; a power user wanting to free the biggest jobs first can't.
- Fix: Surface file size in the row, or rename the option explicitly. Ideally add size to the payload.
- Suggested command: clarify

### [P3] Pricing page omits the FAQ the design spec specifies
- What: DESIGN_SPEC.md Screen 2 lists a 3-item FAQ; PricingPage.tsx has none.
- Why it matters: Checkout concerns ("Can I cancel anytime?", "Do credits roll over?") are exactly what converts on a pricing page.
- Fix: Add a short FAQ accordion reusing the Support pattern.
- Suggested command: polish

## Persona Red Flags

### Jordan / First-timer
- Primary action: "Convert now — no sign-up" -> drop -> pick format -> Start.
- Red flags: The Convert panel shows two side-by-side pickers (From/To) before a drop zone. A first-timer with a .docx who doesn't touch the pickers hits ".docx isn't a supported source format" — the default From is pdf, and auto-switch only fires on drop, not before. The mismatch error is the first thing they learn. Also, the Guest page says "You'll see it in your history below" while app Convert says "in the queue below" — same concept, two names.

### Alex / Power-User
- Primary action: Select many files -> mass convert; organize a large Drive.
- Red flags: Mass-convert requires all selected files share one source extension, and the Convert button is just disabled with a tooltip ("Select files of the same type to convert") — a silent disabled button until they find the tooltip. No multi-target batch (N files -> one target only). "New folder" default is literally new_folder and selects all its text. Drag-to-reorganize is mouse-only at the surface; the keyboard path is buried in each card's menu -> "Move to...".

### Casey / Mobile
- Primary action: Convert quickly from a phone.
- Red flags: The FormatPicker popover is w-[520px] max-w-[90vw] with a w-40 category sidebar + grid-cols-3 format grid — at 375px it crushes density; picking "To" is the most cramped interaction in the app. The Convert page stacks From/To picker -> big morph -> full-width drop zone -> "Start conversion", pushing the primary CTA below the fold. The Files page is heavy: grid-cols-3 folders (names truncate) and auto-fill minmax(12.5rem) files (about 2 cards/row -> lots of scroll).

### Sam / Accessibility
- Primary action: keyboard-navigate Convert + Files; use a screen reader.
- Red flags: Dropdown and FormatPicker declare role="listbox"/role="option" but implement no arrow-key navigation or typeahead — a screen-reader user hears "listbox" and expects Up/Down/Home/End that don't exist. The Modal restores focus but does not trap it (can Tab out into the background). SelectionCheckbox is a span aria-label with no checkbox role, and the selectable card root is role="button" but never announces aria-pressed/checked. Toasts auto-dismiss after 4.5s inside a pointer-events-none container — a SR user can easily miss transient success/error messages. (Positive: the themed Modal's role=dialog, aria-modal, Escape, :focus-visible, and icon-button aria-labels are genuinely good.)

## Minor Observations

- TXT format color == --color-muted (#8A919B), so TXT chips read as disabled gray — a differentiation miss in the format palette.
- Settings "Save changes" is a ghost save — toasts "Profile saved" but never calls the API or persists the edited email.
- Toast layer: fixed w-80, pointer-events-none, no max-stack clamp; long messages can clip.
- Two slightly different "clear history" flows (Guest vs app) with different wording.
- Support "Report an issue" navigates to mailto: with no in-app confirmation.
- Nav redundancy: Convert + inline Queue + Dashboard "Recent conversions" + History + Queue surface the same job in four places with different column sets.
- Three parallel popover implementations (ErrorButton/CardMenu/Dropdown) each with own outside-click/Escape/portal logic.
- index.html has no meta description and no theme-color (missing meta signal, not a11y).
